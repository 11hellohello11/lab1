
# F-01. Відсутність заголовків безпеки у відповіді HTTP 500

**Статус:** Fixed
**Актив:** HTTP-відповіді застосунку SecureLab
**Компонент:** ASP.NET Core middleware, `src/SecureLab.Api/Program.cs`
**Пріоритет:** P2

## Передумови і межі огляду

Перевірку виконано в локальному навчальному середовищі SecureLab на основі версії `v0.5.0`.

- Review-start commit: `71af2769ea5c3ad85d8cc8b723f406436c23df93`.
- Гілка: `lab/6-hardening-review`.
- Середовище: Windows, .NET SDK 10.0.401, ASP.NET Core API, PostgreSQL у Docker Compose.
- Профіль: Production із контрольовано недоступною базою даних.
- Маршрут: `POST /api/auth/login`.
- Тестові дані: синтетичний пароль без використання реальних облікових даних.
- Обмеження: перевірка виконувалася лише на власному локальному стенді.

Для відтворення використовувався скрипт `Production.ps1` із параметром `-Mode broken`, який налаштовує недоступний порт PostgreSQL `54399`.

## Відтворення

1. Запущено API у середовищі Production із недоступним підключенням до PostgreSQL.
2. Надіслано POST-запит до `/api/auth/login` із синтетичними тестовими даними.
3. Отримано HTTP `500 Internal Server Error` у форматі `application/problem+json`.
4. Перевірено наявність заголовків `X-Content-Type-Options` та `Referrer-Policy`.

**Очікуваний результат:** відповідь HTTP 500 містить `X-Content-Type-Options: nosniff` і `Referrer-Policy: no-referrer`.

**Фактичний результат:** обидва заголовки відсутні, хоча у відповідях HTTP 200, 400 і 404 вони присутні.

## Вплив і ймовірність

**Статус перевірки:** спостережено локально.

Недолік спричиняв непослідовне застосування HTTP-заголовків безпеки. У разі необробленого серверного винятку відповідь не містила налаштувань, що обмежують MIME-sniffing і передавання інформації через заголовок Referer.

Для відтворення сценарію потрібне виникнення необробленої серверної помилки. У навчальному середовищі її викликано контрольованою недоступністю PostgreSQL.

Безпосереднього витоку даних під час перевірки не встановлено. Відповідь HTTP 500 зберігала безпечний формат Problem Details і не розкривала stack trace або рядок підключення.

Пріоритет P2 визначено з урахуванням обмеженого впливу недоліку та необхідності забезпечення однакових механізмів захисту для різних класів HTTP-відповідей.

## Першопричина

У початковій конфігурації `Program.cs` middleware для встановлення заголовків безпеки розташовувався після `UseExceptionHandler()`.

Під час обробки необробленого винятку механізм формування відповіді про помилку очищував раніше встановлені заголовки. Унаслідок цього `X-Content-Type-Options` і `Referrer-Policy` не потрапляли до кінцевої HTTP-відповіді 500.

## Виправлення

Middleware для встановлення заголовків перенесено перед `UseExceptionHandler()`.

Додатково застосовано `Response.OnStarting()`, що забезпечує встановлення заголовків безпосередньо перед надсиланням HTTP-відповіді.

Збережено такі значення:

- `X-Content-Type-Options: nosniff`;
- `Referrer-Policy: no-referrer`.

Інші маршрути API, механізми автентифікації та авторизації не змінювалися.

Виправлення виконано у файлі `src/SecureLab.Api/Program.cs` у гілці `lab/6-hardening-review`. Остаточний commit буде зафіксовано після завершення перевірок.

## Retest

Після виправлення повторно запущено API у Production із недоступною базою даних та надіслано той самий POST-запит до `/api/auth/login`.

**Фактичний результат:**

- HTTP `500 Internal Server Error`;
- `Content-Type: application/problem+json`;
- `X-Content-Type-Options: nosniff`;
- `Referrer-Policy: no-referrer`.

**Результат: PASS.** Обидва заголовки присутні у відповіді HTTP 500. Початковий недолік не відтворюється.

## Positive regression

Після виправлення застосунок запущено у звичайному середовищі Development.

GET-запит до `/health` повернув HTTP `200 OK` із заголовками `X-Content-Type-Options: nosniff` і `Referrer-Policy: no-referrer`.

Додатково виконано автоматизоване тестування:

`dotnet test SecureLab.sln -c Release`

Результат: 14 тестів успішні, 0 помилок, 0 пропущених.

**Результат: PASS.** Виправлення не порушило поведінку, охоплену виконаними перевірками.

## Залишковий ризик

Застосування зазначених заголовків не замінює серверну валідацію, автентифікацію, авторизацію та захист від XSS.

Під час перевірки досліджено контрольовану помилку підключення до PostgreSQL, але не всі можливі типи серверних винятків. Повнота застосування заголовків також залежить від подальших змін HTTP-конвеєра.

Розширене налаштування Content-Security-Policy не входить до обраного достатнього рівня лабораторної роботи.
