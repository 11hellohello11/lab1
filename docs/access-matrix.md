## Правило авторизації для GET /api/incidents/{id}

Для читання деталей інциденту сервер перевіряє автентифікованого користувача, його роль і належність ресурсу.

- Анонімний користувач отримує HTTP 401 Unauthorized.

- Reporter читає власний інцидент із HTTP 200 OK.

- Reporter не отримує чужий інцидент: HTTP 404 Not Found.

- Analyst може читати інциденти для аналізу: HTTP 200 OK.

- Administrator не отримує автоматичного обходу правил власності.

- Ідентифікатор та роль користувача визначаються тільки з verified principal.

## Політика HTTP-відмов

Для чужого інциденту обрано HTTP 404 Not Found.

Таку саму відповідь сервер повертає для неіснуючого інциденту. Це зменшує можливість визначення факту існування чужого ресурсу.

Відповіді для чужого й неіснуючого інциденту повинні мати однакові HTTP status, Content-Type та стабільні поля JSON. Допускається відмінність значень traceId.

## Перевірки

A-02: власник читає власний інцидент — HTTP 200.

A-03: інший Reporter читає чужий інцидент — HTTP 404.

A-03R: Analyst читає інцидент Alice — HTTP 200.

Анонімний запит до захищеної операції — HTTP 401.
